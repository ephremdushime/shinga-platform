Integration Guide

SMS Notifications

Complete Africa's Talking SMS integration for SHINGA. Every key platform event — job posted, application received, worker contacted, payment confirmed, verification approved — triggers a targeted SMS to the right person, in Kinyarwanda or English.

✅ What this covers
Provider: Africa's Talking — Rwanda local rates (~RWF 28–35/SMS)
8 notification triggers covering both worker and employer sides
Bilingual templates — Kinyarwanda (default) + English
Rate limiting — max 5 SMS per user per hour, configurable
Delivery logging — every SMS stored in Supabase, visible in admin
Async queue — SMS never blocks your API response time

Africa's Talking Setup

  1. Create account at africastalking.com
  2. Go to SMS → Sender IDs → request SHINGA as sender ID (1–3 days in Rwanda)
  3. Go to Settings → API Key → copy your key
  4. Fund your AT account — minimum RWF 5,000 to start sending
  5. For testing: use username sandbox with any API key — no real SMS sent
⚠️ Apply for your Sender ID immediately
Without an approved sender ID, messages arrive from a random short code. Apply for SHINGA on day one — approval takes 1–3 business days. Use sandbox mode during that wait.

Core SMS Library

Create lib/shinga/sms.ts. All notification sending flows through notify(). Direct sends use sendSms().

lib/shinga/sms.ts
// ═══════════════════════════════════════════════════════
// SHINGA — SMS Library (Africa's Talking)
// ═══════════════════════════════════════════════════════
import { createServerClient } from './supabase'
import { SMS_TEMPLATES }     from './sms-templates'

export type SmsEvent =
  | 'job_posted'         | 'application_received'
  | 'application_sent'   | 'worker_contacted'
  | 'payment_confirmed'  | 'marked_hired'
  | 'verification_approved'
  | 'job_expiry_warning' | 'wallet_low'

export interface SmsPayload {
  to:      string                        // +250XXXXXXXXX
  event:   SmsEvent
  lang?:   'en' | 'rw'                 // default: process.env.SMS_DEFAULT_LANG
  data:    Record<string, string>        // template variables
  userId?: string                        // for rate limiting + logging
}

// ── DIRECT SEND ──────────────────────────────────────

export async function sendSms(
  to: string, message: string,
  event?: SmsEvent, userId?: string
): Promise<void> {

  if (process.env.SMS_ENABLED === 'false') {
    console.log(`[SMS SKIP] ${to}: ${message}`)
    return
  }

  // Rate limit
  if (userId && await isRateLimited(userId)) {
    console.warn(`[SMS] Rate limited: ${userId}`)
    return
  }

  try {
    const res = await fetch(
      'https://api.africastalking.com/version1/messaging',
      {
        method: 'POST',
        headers: {
          'apiKey':       process.env.AT_API_KEY!,
          'Content-Type': 'application/x-www-form-urlencoded',
          'Accept':       'application/json',
        },
        body: new URLSearchParams({
          username: process.env.AT_USERNAME!,
          to, message,
          from: process.env.AT_SENDER_ID || 'SHINGA',
        }).toString(),
      }
    )
    const result    = await res.json()
    const recipient = result.SMSMessageData?.Recipients?.[0]

    // Log every send — fire and forget
    logSms({
      phone: to, message,
      event: event || 'payment_confirmed',
      status: recipient?.status  || 'unknown',
      cost:   recipient?.cost    || '0',
      user_id: userId,
    }).catch(console.error)

  } catch (err) {
    console.error('[SMS] Failed:', err)
  }
}

// ── TEMPLATE-BASED NOTIFY ────────────────────────────

export async function notify(payload: SmsPayload): Promise<void> {
  const lang    = payload.lang
    ?? (process.env.SMS_DEFAULT_LANG as 'en' | 'rw')
    ?? 'rw'
  const tpl     = SMS_TEMPLATES[payload.event]?.[lang]
  if (!tpl) { console.warn(`[SMS] No template: ${payload.event}`); return }

  const message = tpl.replace(
    /\{\{(\w+)\}\}/g,
    (_, k) => payload.data[k] ?? `[${k}]`
  )
  await sendSms(payload.to, message, payload.event, payload.userId)
}

// ── RATE LIMIT ───────────────────────────────────────

async function isRateLimited(userId: string): Promise<boolean> {
  const supabase = await createServerClient()
  const limit    = parseInt(process.env.SMS_RATE_LIMIT_PER_HOUR || '5')
  const hourAgo  = new Date(Date.now() - 3_600_000).toISOString()
  const { count } = await supabase
    .from('sms_log')
    .select('id', { count: 'exact', head: true })
    .eq('user_id', userId)
    .gte('created_at', hourAgo)
  return (count ?? 0) >= limit
}

// ── DB LOG ───────────────────────────────────────────

async function logSms(d: {
  phone: string; message: string; event: string;
  status: string; cost: string; user_id?: string
}) {
  const supabase = await createServerClient()
  await supabase.from('sms_log').insert(d)
}

5 — Marked as Hired

Sent to the worker when employer clicks "Mark as Hired" in their employer dashboard.

app/api/applications/[id]/hire/route.ts
export async function POST(_: NextRequest, { params }) {
  const user     = await getUser()
  if (!user) return NextResponse.json({ error: 'Unauthorized' }, { status: 401 })

  const supabase = await createServerClient()
  const { data: app } = await supabase
    .from('applications')
    .update({ status: 'hired' })
    .eq('id', params.id)
    .select('*, worker:workers(*), job:jobs(*)')
    .single()

  if (!app) return NextResponse.json({ error: 'Not found' }, { status: 404 })

  await notify({
    to:    app.worker.phone,
    event: 'marked_hired',
    data:  {
      employer: user.user_metadata?.full_name || 'The employer',
      job:      app.job.title,
    },
    userId: app.worker_id,
  })

  return NextResponse.json({ success: true })
}

7 — Job Expiry Warning

A cron job runs daily at 8AM Kigali time. It finds jobs expiring in exactly 3 days and SMS the employer to renew.

app/api/cron/expiry-warnings/route.ts
// vercel.json: { "crons": [{ "path": "/api/cron/expiry-warnings", "schedule": "0 6 * * *" }] }
export async function GET() {
  const supabase = await createServerClient()
  const in3Days  = new Date(Date.now() + 3*24*60*60*1000)
  const in4Days  = new Date(Date.now() + 4*24*60*60*1000)

  const { data: jobs } = await supabase
    .from('jobs')
    .select('id, title, employer_id, employer:profiles(phone, sms_lang)')
    .eq('status', 'active')
    .gte('expires_at', in3Days.toISOString())
    .lt('expires_at',  in4Days.toISOString())

  for (const job of jobs ?? []) {
    if (!job.employer?.phone) continue
    await notify({
      to:    job.employer.phone,
      event: 'job_expiry_warning',
      lang:  job.employer.sms_lang || 'rw',
      data:  { title: job.title },
      userId: job.employer_id,
    })
  }

  return NextResponse.json({ sent: jobs?.length ?? 0 })
}

8 — Wallet Low

Triggered automatically after any debit from a user's credit wallet when balance falls below RWF 3,000.

Add to end of fulfillPayment() in lib/shinga/payments.ts
// After marking payment 'completed', check wallet balance
const LOW_THRESHOLD = 3000

const { data: wallet } = await supabase
  .from('wallets')
  .select('balance')
  .eq('user_id', payment.user_id)
  .single()

if (wallet && wallet.balance < LOW_THRESHOLD) {
  const { data: profile } = await supabase
    .from('profiles')
    .select('phone, sms_lang')
    .eq('id', payment.user_id)
    .single()

  if (profile?.phone) {
    await notify({
      to:    profile.phone,
      event: 'wallet_low',
      lang:  profile.sms_lang || 'rw',
      data:  { balance: wallet.balance.toLocaleString() },
      userId: payment.user_id,
    })
  }
}

Database Schema Addition

Run this in Supabase SQL Editor to add the SMS log table and user language preferences.

Add to shinga-schema.sql
-- ── SMS LOG ──────────────────────────────────────────
create table sms_log (
  id         bigserial primary key,
  user_id    uuid references profiles(id) on delete set null,
  phone      text not null,
  event      text not null,
  message    text not null,
  status     text default 'queued',
  cost       text,
  created_at timestamptz default now()
);

create index sms_user_idx    on sms_log(user_id);
create index sms_event_idx   on sms_log(event);
create index sms_created_idx on sms_log(created_at desc);

-- ── USER SMS PREFERENCES (add to profiles) ───────────
alter table profiles
  add column if not exists sms_lang    text default 'rw'
    check (sms_lang in ('rw', 'en')),
  add column if not exists sms_enabled boolean default true;

-- ── RLS ──────────────────────────────────────────────
alter table sms_log enable row level security;

create policy "sms_own_read" on sms_log
  for select using (user_id = auth.uid());

Async SMS Queue

For high-traffic moments, queue SMS instead of sending inline — so your API never waits on Africa's Talking.

lib/shinga/sms-queue.ts
// Use queueSms() instead of notify() when you want non-blocking sends.
// A Supabase Edge Function or Vercel cron drains the queue every 30s.

export async function queueSms(payload: SmsPayload): Promise<void> {
  const supabase = await createServerClient()
  const lang     = payload.lang ?? 'rw'
  const tpl      = SMS_TEMPLATES[payload.event]?.[lang]
  if (!tpl) return
  const message  = tpl.replace(/\{\{(\w+)\}\}/g, (_, k) => payload.data[k] ?? `[${k}]`)

  await supabase.from('sms_queue').insert({
    to: payload.to, message,
    event:   payload.event,
    user_id: payload.userId,
    status:  'pending',
  })
}
